# otus-1c-gitflow

Учебный репозиторий: процесс **GitFlow** для управления изменениями и выпуском релизов конфигурации 1С.

## Ветки

| Ветка | Назначение |
|---|---|
| `master` | Стабильные релизы. Изменения попадают только через PR из `develop`. На каждый релиз ставится тег `vX.Y.Z` и публикуется cf-файл. |
| `develop` | Интеграционная ветка разработки. Изменения попадают через PR из `storage_1c` (или feature-веток). |
| `storage_1c` | Зеркало хранилища конфигурации 1С. Заполняется только скриптом синхронизации (gitsync), вручную не редактируется. |
| `branch_sync_hran` | Служебная ветка синхронизации: фиксирует последний обработанный коммит хранилища. |

## Поток изменений

```
Хранилище 1С ──gitsync──▶ storage_1c ──PR──▶ develop ──PR──▶ master ──vrunner compile──▶ release.cf
```

1. Разработчик помещает изменения в хранилище 1С с комментарием вида `TASK-<номер> <описание>`.
2. `sync_storage.bat` выгружает новые версии хранилища в ветку `storage_1c` — по коммиту на версию, автор и комментарий сохраняются.
3. Открывается Pull Request `storage_1c → develop`, проходит ревью и сливается.
4. Для выпуска открывается Pull Request `develop → master` и сливается.
5. `build_release.bat` собирает cf-файл из исходников `master` командой `vrunner compile`, ставится тег, cf публикуется в GitHub Releases.

## Структура

```
src/                 выгрузка конфигурации (формат Конфигуратора), ведётся gitsync
sync_storage.bat     синхронизация хранилища -> storage_1c
build_release.bat    сборка cf из master
.gitignore
```

## Требования

- Платформа 1С:Предприятие 8.3
- Git
- OneScript + пакеты `gitsync`, `vanessa-runner` (`opm install gitsync vanessa-runner`)
